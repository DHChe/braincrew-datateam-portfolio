# Domain Docs

이 문서는 Matt Pocock 엔지니어링 스킬이 저장소의 공식 용어와 기술 결정을 읽는 방법을 정의한다.

## 작업 전 확인할 문서

- 루트의 `CONTEXT.md`
- 작업 영역과 관련된 `docs/adr/` 문서
- `AGENTS.md`의 Standards & References에 연결된 기존 결정 및 설계 문서

파일이 아직 없다면 오류로 처리하지 않는다. 실제 용어나 중요한 결정이 확정될 때 `domain-modeling`을 통해 작성한다.

## 문서 구조

이 저장소는 단일 문맥 구조를 사용한다.

- `CONTEXT.md`: 프로젝트의 공식 용어와 의미
- `docs/adr/`: 변경하기 어려운 기술 및 설계 결정
- 기존 결정 문서: 평가 범위와 구현 계약

`CONTEXT.md`와 `docs/adr/`은 설정을 위해 빈 파일이나 예제 문서로 미리 만들지 않는다. 실제로 해결된 용어나 결정이 있을 때 생성한다.

## 용어 사용 규칙

이슈 제목, 테스트 이름, 구현 문서에서는 `CONTEXT.md`의 공식 용어를 사용한다. 기존 용어와 다른 표현이 필요하면 임의로 추가하지 않고 용어 결정을 먼저 기록한다.

기존 ADR 또는 고정 결정 문서와 충돌하는 구현은 충돌 사실을 명시하고, 기존 결정을 조용히 덮어쓰지 않는다.
